I have updated my OpenAPI spec at inputs/api_reference/openapi.json. Regenerate the API reference docs for my Docusaurus website.

## Context

This project uses `docusaurus-plugin-openapi-docs` and `docusaurus-theme-openapi-docs` to render interactive API reference pages from the OpenAPI spec.

The API docs live in a **separate docs plugin instance** (`api-docs/`) to avoid
conflicting with the autogenerated sidebar used by the main `docs/` directory.

- OpenAPI input spec: inputs/api_reference/openapi.json
- Introduction input source: inputs/api_reference/introduction.md
- Version input source: inputs/version.txt
- Generated output directory: api-docs/ (gitignored — fully regenerated each time)
- Generated sidebar: api-docs/sidebar.ts
- Generated introduction page: api-docs/backend-api.info.mdx (route: /api/backend-api)

## Steps

1. Remove the api-docs/ directory if it exists:

   rm -rf api-docs

2. Create a fresh empty directory:

   mkdir -p api-docs

3. The `@docusaurus/plugin-content-docs` instance for api-docs requires
   `sidebarPath` to point to an existing file at startup. But the sidebar
   doesn't exist yet (it's generated in the next step). Temporarily set
   `sidebarPath` to `false` in docusaurus.config.ts:

   Change:  sidebarPath: './api-docs/sidebar.ts',
   To:      sidebarPath: false,

4. Generate the API docs from the spec:

   npx docusaurus gen-api-docs all

5. Customize the generated API introduction page:

   - Read intro markdown from: `inputs/api_reference/introduction.md`.
   - Read the version string from: `inputs/version.txt`.
   - Target generated file: `api-docs/backend-api.info.mdx`
   - Keep the generated `id`, `sidebar_label`, `sidebar_position`, `hide_title`,
     `custom_edit_url`, and imports unchanged.
   - Set the page frontmatter title to:
     `title: "DeepAlphaResearch.ai API Reference"`
   - Set the visible H1 heading to:
     `children={"DeepAlphaResearch.ai API Reference"}`
   - Set the version badge content to:
     `children={"Version: <value from inputs/version.txt>"}`
   - Insert the intro markdown body immediately after the closing `</Heading>` line.
   - If intro markdown already exists there, replace it with the new content from
     `inputs/api_reference/introduction.md`.
   - Preserve valid MDX formatting in the final file.

6. Restore `sidebarPath` in docusaurus.config.ts:

   Change:  sidebarPath: false,
   To:      sidebarPath: './api-docs/sidebar.ts',

7. Fix the generated sidebar export. The plugin generates:

      export default sidebar.apisidebar;

   This is wrong — Docusaurus expects a SidebarsConfig object, not an array.
   Change that line to:

      export default sidebar;

8. Verify the intro page content is correct and the site builds without errors:

   - Open `api-docs/backend-api.info.mdx` and confirm:
     - frontmatter title is `DeepAlphaResearch.ai API Reference`
     - heading is `DeepAlphaResearch.ai API Reference`
     - version badge uses the value from `inputs/version.txt`
     - body contains the exact text from `inputs/api_reference/introduction.md`
       after the `</Heading>` block
   - Confirm the API intro route `/api/backend-api` shows that introduction content.

   npx docusaurus build

## Setup (only needed if the plugin is not yet installed)

If the packages `docusaurus-plugin-openapi-docs` and `docusaurus-theme-openapi-docs` are not in package.json, run:

   npm install docusaurus-plugin-openapi-docs docusaurus-theme-openapi-docs

Then make the following configuration changes:

### docusaurus.config.ts

1. Add the theme to the `themes` array:

   themes: ['@docusaurus/theme-mermaid', 'docusaurus-theme-openapi-docs'],

2. Add a top-level `plugins` array with both the OpenAPI docs generator and a
   separate docs plugin instance for the API pages:

   plugins: [
     [
       'docusaurus-plugin-openapi-docs',
      {
        id: 'api',
        docsPluginId: 'api-docs',
        config: {
          backend: {
            specPath: 'inputs/api_reference/openapi.json',
            outputDir: 'api-docs',
            sidebarOptions: {
              groupPathsBy: 'tag',
            },
          },
        },
      },
     ],
     [
       '@docusaurus/plugin-content-docs',
       {
         id: 'api-docs',
         path: 'api-docs',
         routeBasePath: 'api',
         docItemComponent: '@theme/ApiItem',
         sidebarPath: './api-docs/sidebar.ts',
       },
     ],
   ],

   IMPORTANT: Do NOT add `docItemComponent` to the preset's docs config.
   It belongs only on the `api-docs` plugin instance above so that regular
   docs pages in docs/ are not affected.

3. Add an "API Reference" navbar item pointing to the separate plugin instance:

   items: [
     {
       type: 'docSidebar',
       sidebarId: 'tutorialSidebar',
       position: 'left',
       label: 'Documentation',
     },
     {
       to: '/api/backend-api',
       position: 'left',
       label: 'API Reference',
     },
   ],

   NOTE: The link must point to `/api/backend-api` (the generated intro page),
   not `/api`, because the plugin does not generate an index page at the root.

### sidebars.ts

No changes needed. The main sidebars.ts continues to use the autogenerated
sidebar for docs/ only. The API sidebar is handled by api-docs/sidebar.ts
which is generated automatically and referenced by the api-docs plugin instance.
